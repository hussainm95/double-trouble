# Double Trouble | شريكين في ورطة

نسخة 0.2.0 — لعبة تعاونية أولية لشخصين. خادم Node.js + Express + Socket.IO، ورسوم Canvas بإسقاط مائل.

## اللعب
1. افتح رابط الخدمة من هاتفك بالعرض، اكتب اسمك واضغط «إنشاء غرفة جديدة».
2. أرسل رابط الغرفة بالزر المخصص أو أرسل رمزها لصديقك.
3. يدخل صديقك من الرابط، يكتب اسمه ويضغط «انضم».
4. تحرّكا بأزرار اللمس، اقتربا من الصندوق ثم اضغطا «امسك / اترك». التوصيل إلى الشاحنة يُحتسب تلقائيًا ويضيف 100 عملة.

يمكن التدريب منفردًا أثناء انتظار الشريك. مقعد المنقطع محفوظ دقيقة، ومحاولة الرجوع تلقائية. بعد دقيقة قد يشغل المقعد لاعب آخر. تحديث الصفحة في نفس التبويب يحاول استعادة الجلسة. خروج صريح يحرر المقعد. الغرف والعملات لا تُحفظ بعد إعادة تشغيل الخادم.

## التشغيل للمطور
- Node.js 22 أو أحدث.
- `npm ci` ثم `npm start`، والمنفذ الافتراضي 3000.
- `npm test` لتشغيل الاختبارات التكاملية (تحتاج متطلبات التطوير).
- `PORT` تحدده الاستضافة تلقائيًا. الملفات الثابتة تُقرأ من مسار المشروع، وليس دليل التشغيل الحالي.

## النشر المختار: Render Free Web Service
المشروع مجهز بملف `render.yaml` وDockerfile بديل. يجب نشره كخدمة ويب Node، وليس Static Site. مصدر الخدمة هو مستودع Git يحتوي هذه الملفات في جذره.

إعدادات الخدمة: خطة Free، البناء `npm ci --omit=dev`، التشغيل `npm start`، مسار الصحة `/health`. استخدم نسخة واحدة فقط؛ حالة الغرف في الذاكرة وليست مشتركة بين عدة خوادم. TLS وWSS ينتهيان عند وكيل الاستضافة، والمتصفح يتصل بنفس مصدر الصفحة؛ لا حاجة لعنوان خادم يدوي أو مفاتيح خاصة في الواجهة.

توثيق رسمي:
- https://render.com/docs/websocket
- https://render.com/docs/free
- https://render.com/docs/your-first-deploy

الخدمة المجانية تنام بعد 15 دقيقة دون حركة واردة، وقد يستغرق إيقاظها نحو دقيقة. إعادة التشغيل تفقد الغرف. لا توجد آلية مصطنعة لإبقائها مستيقظة.

## تقرير التحقق — 16 أكتوبر 2026
نجح `npm test`: اختباران تكامليان، أحدهما يغطي سيناريوهات متعددة:
- تشغيل خادم فعلي محلي واستقبال HTTP وطلب فحص الصحة.
- عميلان Socket.IO مستقلان بوسيلة WebSocket فعلية، وإنشاء غرفة وانضمامها.
- تحديث حالة اللاعبين لدى الطرفين.
- الحركة، التقاط الصندوق، توصيله وتطابق العملات بين الطرفين.
- منع لاعب ثالث، ومنع إعادة الانضمام أثناء العضوية، ورفض الغرفة غير الموجودة.
- عزل غرفة ثانية عن الأولى.
- إرسال 1000 رسالة حركة متتابعة لا يسمح بالقفز في الخريطة: الحركة تُحسب في نبض الخادم.
- تجاهل مدخلات حركة غير محدودة، وحفظ إحداثيات سليمة.
- إعادة الاتصال برمز سري خاص بالجلسة مع الاحتفاظ بالهوية والنتيجة.
- تحرير المقعد بعد مهلة، وحذف الغرفة الخالية.
- اتصال Socket.IO بوسيلة HTTP long-polling البديلة.

نجح فحص صياغة JavaScript. فحص `npm audit --omit=dev` أبلغ عن صفر ثغرات معروفة وقت الفحص.

لم تُجر اختبارات متصفح أو محاكاة Safari/Chrome أو اختبارات هاتفين فعليين؛ أداة المتصفح المطلوبة لم تكن متاحة. اختبارات الشبكة المحلية لا تثبت الأداء عبر شبكات الهاتف أو الإنترنت العام. الواجهة مجهزة مبدئيًا لخصائص Safari/Chrome الحديثة: Pointer Events، مناطق الشاشة الآمنة، ارتفاع ديناميكي مع بديل، تنبيه الاتجاه العمودي، ومسح الحركة عند مغادرة الصفحة/تغيير الاتجاه. يجب التحقق بصريًا وعلى الهاتفين بعد النشر.

## ما يحتاج تطويرًا
- مدينة مفتوحة حقيقية وقيادة ومهام متنوعة وفيزياء كوميدية واصطدامات لم تُنفذ؛ هذه نسخة توصيل بسيطة.
- لا حفظ دائم للعملات، حسابات، أو دعم عدة نسخ من الخادم.
- رسوم الرموز التعبيرية تختلف بين الأجهزة. لا ضمان لتطابق شكلها.
- لا تنعيم بصري متقدم للحركة أو تعويض زمن الشبكة؛ يلزم تقييم الأداء بعد النشر.
- رمز الغرفة ليس نظام حسابات؛ شاركه فقط مع صديقك.

## التحقق بعد النشر
افتح `/health` وتأكد من `{ "ok": true }`. نفّذ سيناريو لاعبين عبر عنوان HTTPS المنشور، ثم جرّبه على Safari في iPhone وChrome في Android بوضع أفقي، بما يشمل اللمس المتزامن وإعادة الاتصال بعد إغلاق الشاشة. لا تُسجَّل هذه الخطوات كناجحة قبل تنفيذها.
